# Delivery Roadmap

## Phase 0 Feasibility and user evidence

- Exercise documented Claude Code and Codex usage sources with real accounts.
- Observe active use, idle behavior, concurrent sessions, missing fields, and a real reset.
- Compare timestamp-aligned readings with each provider's own display.
- Run seven-day usage diaries with developers who pay for at least two services.

Exit when the sources are sustainable enough for the advertised scope and a repeated planning problem appears in real work.

## Phase 1 Mac private alpha

- Implement two provider adapters and local snapshot history.
- Show five-hour and weekly windows independently.
- Display observation age, source, quality, and connection repair actions.
- Measure idle CPU, wakeups, memory, and reconnect behavior.

Exit when fresh readings agree with provider displays within their precision and ordinary setup requires no live assistance.

## Phase 2 Capacity planning

- Add planned work blocks and user-defined reserves.
- Start with a transparent recent-pace baseline.
- Return a range or insufficient-history state rather than false precision.
- Evaluate false warnings and missed exhaustion events.

Exit when people make useful work decisions that a basic meter does not support.

## Phase 3 iPhone companion

- Synchronize normalized snapshots only after explicit opt-in.
- Show when the phone last heard from its collector.
- Add widgets and deduplicated notifications designed for delayed refresh.
- Test sleeping Macs, offline periods, account changes, and revocation.

## Later work

Android, API spending, additional providers, and paid plans remain gated on demonstrated demand and adapter maintenance capacity.
